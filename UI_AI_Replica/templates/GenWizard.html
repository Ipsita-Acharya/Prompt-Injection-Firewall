No problem at all. If you can't use GenWizard, you will use Automation Anywhere's built-in, traditional IDP solution called **Document Automation**. This method is more structured than GenAI. Instead of *telling* the AI what you want, you *train* it by showing it examples. Think of it like training a new employee on how to read a specific form. ### The Core Concept: The "Learning Instance" The heart of Document Automation is the **Learning Instance**. A Learning Instance is a mini-AI model that you train to understand one specific type of document (e.g., "Vendor Invoices," "Purchase Orders," or "Medical Forms"). The process is split into two main phases: 1. **Training Phase:** You teach the Learning Instance what to look for. (Done once in the Control Room). 2. **Automation Phase:** Your bot uses the trained Learning Instance to process new documents. (Done in the Bot Editor). --- ### Phase 1: Training the Learning Instance (In the Control Room) This is where you do the initial setup and teaching. #### **Step 1: Create a Learning Instance** 1. Log in to your Automation Anywhere Control Room. 2. Navigate to **Manage > Learning Instances**. 3. Click **Create Learning Instance**. 4. Give it a name (e.g., `InvoiceProcessing`). 5. Select the document type (e.g., Invoices). 6. Upload a few sample documents (5-10 is a good start) that represent the variety you expect to see. #### **Step 2: Define the Fields You Want to Extract** 1. Once the instance is created, you'll be taken to the Document Automation designer. 2. On the right-hand panel, you will see a list of standard fields for that document type (e.g., `Invoice number`, `Invoice date`). 3. You can add custom fields if needed. For example, click **Add form field** and create a field called `PurchaseOrderNumber`. #### **Step 3: Train the Model (The "Teaching" Part)** This is the most important step. You need to show the AI where to find the information on your sample documents. 1. The first sample document will be displayed. 2. Click on a field name in the right-hand panel (e.g., `Invoice number`). 3. On the document image, **click and drag a box** around the actual invoice number. 4. The system will automatically read the text in the box and associate it with the `Invoice number` field. 5. Repeat this process for **all the fields** you need on a few of your sample documents. 6. When you are done, click **Save and next**. The AI will start learning from your examples. #### **Step 4: Publish the Learning Instance** After training, you need to "publish" the Learning Instance to make it available for your bots to use. This usually involves a "Set to Production" button. --- ### Phase 2: Building the Bot to Use the Learning Instance (In the Bot Editor) Now you build the RPA bot that will send new documents to your trained model. #### **Step 1: Set Up Your Bot and File Loop** This is the same as before: create a new bot and use a **Loop** action to iterate through each file in an input folder. #### **Step 2: Use the Document Automation Actions** Inside the loop, you will use two main actions from the **Document Automation** package. 1. **Action 1: `Process documents`** * Drag this action into your loop. * Select the Learning Instance you created (e.g., `InvoiceProcessing`). * Provide the full file path of the document you are processing: `$file{path}$\$file{name}$.$file{extension}$`. * This action sends the document to your trained model and saves the results. 2. **Action 2: `Get all extracted fields`** * Drag this action right below the `Process documents` action. * This action retrieves the data that was extracted. * In the "Assign output to a variable" field, create a new **Table** variable (e.g., `tExtractedData`). This table will have two columns: Field Name and Field Value. #### **Step 3: Loop Through the Extracted Data** Because the data is in a table, you need to loop through it to get the values. 1. Drag a new **Loop** action inside your main file loop. 2. Set the iterator to `For each row in a data table`. 3. Select your table variable `tExtractedData`. 4. Create a **Record** variable to hold the current row's data (e.g., `rCurrentField`). #### **Step 4: Use the Data with an If Condition** Inside this second loop, you can check the field name and then use its value. 1. Drag an **If** action into the inner loop. 2. Set the condition: `If String condition: $rCurrentField[0]$ == "InvoiceNumber"`. * `$rCurrentField[0]$` is the field name (the first column). * `$rCurrentField[1]$` is the field value (the second column). 3. Inside the **If** block, you can now use the value. For example, create a **String** variable called `sInvoiceNumber` and use an **Assign** action to set its value: `sInvoiceNumber = $rCurrentField[1]$`. 4. Repeat this with `Else If` blocks for all the other fields you need (`VendorName`, `TotalAmount`, etc.). #### **Step 5: Final Actions** After the inner loop finishes, you will have all your extracted data stored in separate string variables (`sInvoiceNumber`, `sVendorName`, etc.). You can now use these variables to perform data entry into SAP or any other application, and then move the processed file. This method requires more setup and training upfront, but it is very reliable for documents that have a somewhat consistent structure.
